# Studio 0.7.62 / ChatGPT Bridge 1.10.2

## SRT output download
Work may render the generated file as a `span` with `role="button"`, `data-file-reference="true"`, and an `aria-label` beginning with Download, rather than an anchor or native button. The bridge now recognizes this file control and its filename metadata.

For SRT file jobs only, a ready interactive file (`aria-busy="false"`) can supply completion evidence when Work omits the final-message marker and response toolbar. The bridge still waits for generation to stop and four stable response polls before clicking. Busy, disabled and hidden file controls are excluded. Multiple distinct SRT files remain an explicit review case.

The existing save order remains: native Chrome download → backend copies and saves the SRT for the job → saved-result acknowledgement → close the owned SRT tab. A download/save failure retains the tab. This update does not automatically resubmit or recover previously failed requests.

## Update
Reload **extensions/chatgpt** and verify version **1.10.2**. Use the complete Studio package if upgrading from an older backend/gateway release. Chrome tabs that already loaded the previous content script need refreshing to use the new script; retain any existing output before doing so.

## Verification
DOM regression tests use the user-reported inline file structure without a final marker or toolbar. Tests cover delayed readiness, active generation, a hidden decoy, ambiguous files, a permanently busy file, existing anchor downloads, and save acknowledgement before tab closure. These are automated simulations, not a live signed-in ChatGPT download.
