# Studio 0.7.148 — Remove repeated job scanning from Merge source loading

Merge Audio + SRT + Media still scanned every media job and decoded its complete payload for each scene after reading the storyboard. This duplicated the expensive work addressed in 0.7.147 and could block backend health checks while loading a large video.

Scene media loading now reuses the storyboard's scoped, validated media history. Loading all video sources reads that snapshot only once. Existing assembly copies are indexed by job and file rather than rescanned for every scene. File resolution and saved-file checks run outside the event loop.

Assembly asset and source catalog queries filter by project/video in SQL. Merge status reads, including render checkpoint files, run outside the event loop. Unassigned and unfiltered history views retain their previous behavior.

Source matching still checks the current concept, prompt and SRT timing. Repeated loads reuse existing copies even when the original download has moved. No database migration, generation or automatic render is triggered.

Validation covers a 200-scene source load with large saved payloads and foreign media/copies, responsive health requests during slow store reads, scoped/unassigned queries, and existing source lineage and render tests. First-time imports still need to copy media and create thumbnails; this change removes redundant catalog and payload processing.

After updating the complete source, restart the backend and Studio. In Merge, use Reload project/video sources (or Load video scene media for the selected SRT), then Check files & preview before rendering.
