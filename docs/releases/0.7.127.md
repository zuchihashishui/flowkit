# Flowkit Studio 0.7.127 — Keep health responsive during WhisperX status reads

The reported GET /health timeout occurs before the production preflight request,
not inside transcription. The client traceback alone cannot establish which
backend operation was delayed on the user's computer.

A regression in 0.7.126 was reproduced locally: synchronous log I/O in the async
WhisperX status route blocked the entire API event loop when the disk read was
slow. WhisperX status and the narration listing now run in FastAPI's worker
thread pool. Source catalog and WhisperX source-readiness checks in production
preflight are also moved off the event loop. The /health timeout stays at five
seconds; this release does not hide a stalled backend by increasing it.

A backend watchdog now logs the backend thread's stack (without local variable
values) if the API event loop stops responding for more than five seconds.
Reports are rate-limited to one per thirty seconds. It does not terminate,
restart, cancel or resubmit jobs. If a different blocking operation remains on
the user's machine, backend.log can identify the call instead of only showing
the Electron timeout.

Validation: 128 backend tests and 30 UI/IPC tests passed. A new regression test
failed on 0.7.126 when a one-second log read blocked health, then passed after
the fix with health responding in under 0.5 seconds while the read continued.
Another test checks health during a slow source catalog read. Watchdog tests
cover genuine blocking and ordinary asynchronous waits. The 21-second cold
environment-check regression remains covered. No transcription was performed
on the user's Windows GPU and its actual stalled stack has not been captured.

Update: fully stop Studio and its backend, extract the complete release over
the installation and reopen Studio. No extension reload is required. If the
health timeout persists, inspect backend.log for “Backend event loop blocked”.

“Existing jobs keep their saved options…” in the WhisperX form is explanatory
help text, not an error message.
