# Studio 0.7.132 — model menu visibility

The Console model-selection script succeeds, but the extension opens the menu
without selecting GPT-5.6 Sol. Comparing them found a visibility difference:
the extension used offsetParent, while the Console script uses getClientRects.
A visible fixed-position menu can have no offsetParent and be excluded.

Bridge 1.16.13 uses getClientRects for model picker and selection-menu visibility,
prioritizes the supplied ModelPickerTriggerLabel control, and matches descendant
model text without requiring that text wrapper to have its own layout box.
Disabled choices, ambiguous choices and unrelated menus remain excluded.
Model verification before submission is retained. Errors now distinguish a
missing option (including observed labels) from a clicked but unverified option.

A fixed-menu regression fixture checks this difference. This identifies a
reproducible code issue, not proof of the exact live page layout on the user's
machine. Reload the extension as 1.16.13 and refresh ChatGPT tabs before testing.
ZIP and SRT downloads continue using DOM click; no debugger permission is added.
