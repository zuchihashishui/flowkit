# Studio 0.7.114 / ChatGPT Gateway extension 1.15.2 — Null setup lock

Fixes the reproduced Start failure: `Cannot read properties of null (reading 'release')`.

The old guard compared `setupOwner?.requestId === worker.requestId`. With no setup owner and an IDLE worker lacking requestId, both expressions were undefined, so the guard passed and called `.release()` on null. The same failure occurred when a running worker released the lock before an idle worker was processed.

A shared release helper now captures and checks the owner, requires a nonempty string request ID, and releases only the matching owner. Restart, SRT cancellation and submission acknowledgment use it. A setup lock belonging to the dedicated JSON-to-SRT request is preserved.

Regression evidence: three new cases fail on the previous extension with the reported null-release error, then pass after the fix. All 65 targeted extension, mode recovery, dedicated SRT and gateway tests pass. Syntax checks pass. Live Windows Chrome was not exercised.

Update the source, then reload **Flowkit ChatGPT Gateway** at chrome://extensions and verify **1.15.2**. Updating only the Electron files does not replace a service worker already loaded by Chrome. Includes the cleanup/restart coordination and diagnostic logging from 0.7.113.
