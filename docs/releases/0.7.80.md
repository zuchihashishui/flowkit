# Studio v0.7.80

The reported generate-media HTTP 500 was caused by a Pydantic Job validation error: saved concepts accepted 50,000 characters but the media queue accepted only 5,000. The request failed before reaching the Google Flow extension.

Image/video jobs now share the 50,000-character Studio limit with saved concepts, preserve all text, and can be reloaded and processed by the worker. Prompt to Image/Video form validation also accepts 50,000 Unicode characters. Voice jobs retain their 5,000-character limit. This is a Studio limit, not a claim about provider acceptance.

Invalid legacy/stored job data returns a 422 with the scene number and validation message, without prompt contents or partially queued batches.

Validation: reproduced the original HTTP 500 with a saved 5,001-character prompt before the fix. After the fix, 69 Python tests and 18 UI tests passed. Coverage includes 5,001/50,000-character image and video prompts, no truncation, queue reload, over-limit rejection, and a mocked end-to-end image worker using the configured Flow project URL/ID, model and aspect ratio. No live Google Flow generation was performed.

Update: close Studio and stop its old backend, replace source with this package, then restart. Existing SRT and prompt data need no reimport. Google Flow Bridge stays 0.6.3; ChatGPT Bridge stays 1.12.3.
