# Studio v0.7.79 / Google Flow Bridge 0.6.3

The manual Open Flow Tab action previously opened new windows in the background, activated existing tabs without focusing their window, and hid runtime/background errors in the panel. This could appear to do nothing.

The button now creates a foreground window when needed or activates an existing Flow tab and brings its window forward, restoring minimized windows while preserving maximized state. Managed Flow tabs are preferred; personal tabs are not adopted for automatic cleanup. The action waits for Chrome before confirming success. The panel shows opening, success, explicit errors, or a 30-second no-response message. This navigation does not need the backend connection.

Automatic generation still uses the saved project URL and existing background-window behavior. This fix does not diagnose or resolve the separately reported generate-media HTTP 500.

Validation: 17 Chrome API/DOM mock tests passed, including create/reuse, minimized windows, discarded tabs, managed project preference, tab/window failures, runtime errors and missing responses. Live Chrome on the user machine was not tested.

Update: close Studio, extract the new source, then Reload Flowkit Google Flow Bridge under chrome://extensions. Check version 0.6.3 and reopen the side panel. If loaded from an older source folder, use Load unpacked on this package's extensions/googleflow folder. ChatGPT Bridge remains unchanged.
