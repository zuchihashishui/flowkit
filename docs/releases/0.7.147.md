# Studio 0.7.147 — Prevent scene snapshot work from blocking the backend

The folder organizer calls the same scene-read endpoint as Studio. That endpoint previously loaded all media jobs and decoded each full job payload again for every scene. Saved project instructions made those payloads large, allowing the synchronous loop to block health checks, WebSocket replies and queue dispatch.

Scene snapshot processing now runs in a worker thread. Media reads are scoped to the exact project and video, each job payload is decoded once, and concept/prompt/media histories are grouped by segment before constructing rows. Output paths and response fields remain unchanged; no jobs are resubmitted and no database migration is required.

Regression checks include a 200-scene dataset with 201 owned media jobs and 400 foreign jobs, plus a blocked-media-store test that verifies the event loop remains responsive. Existing scene lineage and workspace-copy tests are also exercised.
