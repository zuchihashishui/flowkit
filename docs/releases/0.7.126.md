# Flowkit Studio 0.7.126 — WhisperX startup and live diagnostics

The reported “Environment check exceeded 20 seconds” was a preflight timeout:
the transcription had not been queued. Preflight now uses the environment
check's own 90-second timeout and subprocess cleanup, rather than cancelling
cold Python/Torch/WhisperX imports after 20 seconds.

WhisperX immediately displays a checking message while Start awaits preflight.
Status/errors are outside the collapsible input form. A live worker log shows
the last 16 KiB of the current scoped job's output, including partial lines and
carriage-return download progress. A narration-list failure no longer suppresses
the transcription status. Queue errors, a stopped queue worker and waiting for
another video's active transcription are explicitly shown.

Also fixed an independent queue-wedge bug: output-directory resolution formerly
ran after setting active_id but before the try/finally block. Resolution failures
now fail the job visibly, release the worker and allow later jobs/retries.
Worker startup, progress and failures are logged to backend.log; subprocess
cleanup always releases the active slot. Windows event-loop errors now describe
how to restart with subprocess support.

The three transcript outputs and timestamp/splitting behavior are unchanged.
No automatic retry or additional generation is introduced.

Validation: 50 backend/progress/preflight tests and 30 UI/IPC tests passed.
The preflight regression uses a real subprocess that takes 21 seconds to return
a successful environment report. Other tests cover partial live stdout before
process exit, queue recovery after output-path failure, visible startup status,
and status display when narration listing fails. These are local tests, not a
transcription on the user's Windows GPU/environment.

Update the full source, stop Studio/backend completely and reopen Studio.
Choose the audio and click Create word JSON. For an existing interrupted job,
use Retry job. No extension reload is required for this update.
