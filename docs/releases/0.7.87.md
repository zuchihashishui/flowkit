# Studio v0.7.87 — Windows WhisperX subprocess startup

The reported preflight traceback ends in asyncio.create_subprocess_exec and
BaseEventLoop._make_subprocess_transport raising NotImplementedError. The
backend was running on a loop without Windows subprocess support, so WhisperX
could not even start its environment check.

The normal python -m agent.main launcher now explicitly uses a Windows Proactor
event-loop policy and awaits Uvicorn Server.serve on that loop. It bypasses
Uvicorn's loop selection, uses one backend worker, and disables Windows hot
reload with a log message. Unix launch/reload behavior is preserved. Existing
WhisperX transcription and cancellation use the same subprocess-capable loop.

Environment-check exceptions now produce a blocked preflight with an actionable
message. Unexpected preflight failures return JSON details and log the traceback.
Malformed worker check responses and nonzero worker exits cannot report success.
Cleanup tolerates a process exiting between inspection and termination.

## Update

Close Studio and stop any separately started old backend. Replace the source
files, then launch Studio normally. If launching the backend by hand, use
python -m agent.main from its virtual environment, rather than uvicorn directly.
Restarting is required: a running event loop cannot be replaced by copying files.
No extension update, model download or dependency reinstall is required by this fix.

Validation: 49 tests passed for the runtime launcher, preflight, WhisperX jobs,
progress, worker reports and real lightweight subprocesses. Python syntax checks
passed. Windows branch behavior is tested with a stand-in subprocess-capable
policy on Linux; this environment cannot run native Windows/WhisperX GPU checks.
