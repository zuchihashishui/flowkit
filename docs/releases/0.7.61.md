# Studio 0.7.61 / ChatGPT Bridge 1.10.1
## Stop an SRT job
Open **SRT → SRT jobs**:
- **Cancel queued job** removes an unsent job from the queue.
- **Stop job** stops a running request or clears a failed job.
- **Stop existing SRT job** appears beside the SRT controls when an existing request blocks preparation, including jobs belonging to another video. It targets only the displayed job ID.

For a running request, the extension attempts to click ChatGPT's Stop control, closes only that worker's owned tab, and releases its reservation. Existing downloads and saved files are retained. A late response cannot revive the cancelled job or alter a newer worker. Already completed jobs remain completed.

## Preparation
Opening SRT with a queued/running job now returns inline status with the stop action instead of the generic HTTP 409. Database rows left RUNNING without an active backend task move to NEEDS_REVIEW; the old tab/files remain available. Queued jobs are never discarded automatically. If no SRT task is executing, preparing SRT restores a Work tab for the oldest queued job using that job’s saved URL and updates its preparation token. The queued request resumes without creating a duplicate. Dispatch is held while the tab is being prepared. Removed-menu recovery instructions are replaced with the SRT controls.

## Upgrade
Replace the complete source and restart Studio, backend and gateway. Reload **extensions/chatgpt**, version **1.10.1**. The gateway uses explicit job IDs for cancellation; old gateway processes must be restarted.

## Verification
Automated tests cover queued cancellation, running cancellation, exact job targeting, retained files, late-response isolation, preparation with pending/orphaned jobs, and the inline UI stop action. Live testing in the user's signed-in browser remains necessary.
