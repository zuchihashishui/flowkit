# Studio 0.7.136 — five concurrent media jobs

The default Flow generation concurrency is now 5. Desktop media queue capacity
uses the same FLOW_GENERATION_MAX_CONCURRENT setting as the Flow client, so
neither layer retains a separate hard-coded limit of 3. Existing explicit
environment overrides remain respected.

Image and video jobs share these slots. The default submission interval stays
3 seconds, voice concurrency stays 1, and cooldown handling is unchanged.
Each completed job frees one slot for the next queued job; the scheduler does
not wait for all five jobs to finish together.

Tests cover concurrency limits of both 3 and 5, queue refill after completed
downloads, cooldown and global submission throttling. Restart Studio/backend
after updating. No extension change is required.
